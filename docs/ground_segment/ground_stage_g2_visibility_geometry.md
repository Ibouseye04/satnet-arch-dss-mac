# Ground Segment Stage G2 Visibility Geometry

## Scope

Stage G2 provides deterministic satellite-to-ground geometric visibility over the selected G1 ground design and the existing operational satellite realization.

For every selected-station and operational-satellite pair at every configured timestep, the model records elevation, Euclidean slant range, and the exact minimum-elevation decision.

Stage G2 models geometric visibility only. A visible satellite-ground pair is not necessarily a viable communications link because antenna, RF, optical, atmospheric, terrain, interference, capacity, and scheduling effects are outside the current model.

Stage G2 does not create ground graph nodes, satellite-ground graph edges, combined graphs, ground failures, service metrics, resilience labels, satellite dataset fields, TGNN features, or trained models.

## Production coordinate-frame audit

The production satellite-position contract is project ECEF in kilometers, generated by the existing `HypatiaAdapter` from SGP4/WGS72 TEME coordinates using its GMST Z-axis rotation.

Canonical frame contract:

```text
frame: project ECEF
frame contract version: hypatia_ecef_gmst_v1
units: kilometers
satellite IDs: nonnegative integers
timestamp: rollout epoch + timestep index × step seconds
```

Ground stations are converted from WGS84 geodetic coordinates to fixed ECEF coordinates. No additional Earth rotation is applied in G2.

The project conversion is not a complete high-precision TEME-to-ITRF transformation. It does not include full Earth-orientation parameters, polar motion, or UT1 corrections. G2 preserves this validated satellite baseline rather than replacing it.

## Frames and typed satellite state

`CoordinateFrame` defines ECEF, TEME, and ECI labels. Visibility Model Version 1 accepts only ECEF. TEME and ECI snapshots fail without fallback conversion.

`FramedSatellitePosition` contains:

- Integer satellite ID.
- Explicit UTC timestamp.
- ECEF `x`, `y`, and `z` in kilometers.
- Explicit frame label.

`OperationalSatellitePositionSnapshot` contains:

- Nonnegative integer timestep index.
- Explicit UTC timestamp.
- Satellite configuration hash.
- Canonically numeric-sorted operational positions.

An operational snapshot remains valid when all satellites have failed. Its positions are empty while its timestep, timestamp, and satellite identity remain explicit.

## Operational satellite reconstruction

The read-only integration adapter constructs `HypatiaAdapter` from the existing `Tier1RolloutConfig`, initializes it through the production TLE and ISL path, and obtains ECEF coordinates through `get_positions_at_step()`.

Canonical visibility is evaluated only against operational satellites after application of the existing persistent failed-node realization. Failed satellite-to-satellite edges do not affect geometric visibility. No new failure sampling occurs.

Failure IDs and edge endpoints are validated as exact in-range integers. Unknown, Boolean, malformed, negative, out-of-range, self, or noncanonical edge identifiers fail.

The adapter creates exactly one source snapshot for every configured timestep, including empty all-failed timesteps. Timestamps are strictly increasing.

## Canonical UTC

Canonical UTC format is always:

```text
YYYY-MM-DDTHH:MM:SS.ffffffZ
```

The encoding always contains six fractional-second digits and uppercase `Z`. Inputs must be timezone-aware and already have UTC offset zero. Naive and nonzero-offset datetimes fail rather than being silently normalized.

The same UTC encoder is used in snapshot hashes, record hashes, JSONL serialization, parsing verification, and replay.

## WGS84 ground model

Named constants:

```text
semi-major axis: 6378.137 km
flattening: 1 / 298.257223563
first eccentricity squared: f × (2 - f)
model version: wgs84_geodetic_ecef_v1
```

Catalog coordinates are interpreted as:

- Geodetic latitude.
- East-positive geodetic longitude.
- WGS84 ellipsoidal height in metres.

For latitude `φ`, longitude `λ`, altitude `h` in kilometers, semi-major axis `a`, and eccentricity squared `e²`:

```text
N = a / sqrt(1 - e² sin²φ)

x = (N + h) cosφ cosλ
y = (N + h) cosφ sinλ
z = (N(1 - e²) + h) sinφ
```

The model does not claim orthometric/geoid-height precision. Satellite coordinates retain SGP4/WGS72 plus the project GMST transform while ground coordinates use WGS84. G2 does not claim sub-meter geodetic accuracy or complete ITRF compliance.

## Topocentric geometry

For satellite and station ECEF coordinates:

```text
Δx = satellite_x - station_x
Δy = satellite_y - station_y
Δz = satellite_z - station_z
```

Using station geodetic latitude `φ` and longitude `λ`:

```text
east  = -sinλ Δx + cosλ Δy
north = -sinφ cosλ Δx - sinφ sinλ Δy + cosφ Δz
up    =  cosφ cosλ Δx + cosφ sinλ Δy + sinφ Δz
```

Then:

```text
slant_range = sqrt(east² + north² + up²)
elevation = atan2(up, sqrt(east² + north²))
```

Elevation is returned in degrees. Slant range is returned in kilometers.

`MIN_VALID_SLANT_RANGE_KM = 1.0e-9` is a computational-degeneracy threshold, not a physical horizon margin. Smaller ranges fail. `GEOMETRY_TEST_ABS_TOL = 1.0e-9` is a test-comparison tolerance and never changes visibility decisions.

## Visibility policy

The policy contains one finite minimum elevation in `[0, 90]` degrees.

The decision is exact and inclusive:

```python
is_visible = elevation_deg >= minimum_elevation_deg
```

No epsilon or hidden horizon margin is added.

Policy identity includes:

- `satnet_ground_visibility_policy` domain/version.
- Minimum elevation encoded through canonical binary64 string serialization.
- Visibility model version.
- Frame contract version.
- WGS84 model version.

## Observation and snapshot structure

Every pair is represented by an immutable `SatelliteGroundLinkObservation` containing:

- Station ID.
- Integer satellite ID.
- UTC timestamp.
- Elevation degrees.
- Slant range kilometers.
- Visibility Boolean.
- ECEF frame.
- Visibility model version.

`GroundVisibilitySnapshot` retains:

- Timestep and timestamp.
- Satellite, ground-design, and policy hashes.
- Explicit visibility, frame, and WGS84 versions.
- Every station-operational-satellite observation.
- The exact visible subset.
- Every station's numerically sorted visible satellite IDs, including empty tuples.
- Snapshot hash.

Observations are sorted by station ID and then numeric satellite ID. Station maps are sorted by station ID.

Snapshot identity uses the `satnet_ground_visibility_snapshot` domain/version, canonical UTC, semantic versions, scientific hashes, every visible and nonvisible observation, and the station mapping. Floating geometry is encoded through G1 canonical float strings, never raw JSON floats.

## Canonical orchestration

The lower-level `evaluate_ground_visibility()` function is a validated-input geometry primitive.

Canonical workflows use `evaluate_ground_design_visibility()`. It:

1. Verifies the satellite hash shared by G1 ground design and source snapshot.
2. Reconstructs the exact persisted G1 selection against the supplied catalog.
3. Verifies catalog, selection, classes, counts, order, and ground-design identity.
4. Resolves exactly those station objects.
5. Invokes the pure geometry primitive.

Region-balanced station selection from G1 and geometric visibility from G2 are independent of satellite constellation design sampling. The selected station set is fixed for one ground design and evaluated against each associated satellite rollout.

## Temporal evaluation

A visibility sequence requires:

- One source snapshot per timestep.
- Contiguous timestep indices from zero.
- Strictly increasing UTC timestamps.
- One satellite configuration identity.
- One fixed ground design.
- One fixed policy.

Output follows timestep order. Repeated evaluation is deterministic.

## Visibility persistence

Canonical artifacts use strict `.jsonl` records sorted by run ID and timestep.

Each `GroundVisibilityRecord` explicitly stores:

- Visibility schema version.
- Run and timestep indices.
- Canonical UTC timestamp.
- Satellite, ground-design, and policy hashes.
- Visibility model, frame contract, and WGS84 versions.
- Snapshot and record hashes.
- Every visible and nonvisible observation.
- Every station visibility mapping.

Record identity uses `satnet_ground_visibility_record` and binds schema, run, timestep, timestamp, semantic versions, and snapshot hash.

The writer validates before touching the destination, emits compact sorted-key UTF-8 JSON, uses Unix newlines, flushes, synchronizes, atomically replaces from a temporary sibling, cleans failures, and refuses overwrite by default.

The reader rejects empty files, empty lines, duplicate JSON keys, malformed JSON, missing or unknown fields, noncanonical timestamps or floats, wrong exact types, unsupported versions, duplicate keys, invalid snapshots, and invalid record hashes.

File path and output directory do not affect identity.

## Completeness and replay

Visibility `(run_id, timestep_index)` keys must exactly equal supplied source keys. Missing, extra, orphan, and duplicate records fail. Every record timestamp and satellite hash must match its source; ground-design and policy hashes must match supplied contracts.

Every satellite timestep has one visibility record, including timesteps containing zero operational satellites.

Replay reconstructs the G1 selection, reevaluates all geometry through production code, recomputes visibility flags, verifies every visible and nonvisible observation, verifies station mappings, and recomputes snapshot and record hashes. Persisted visibility flags are never trusted without recomputation.

## Diagnostic harness

The nontraining geometry diagnostic covers:

- Overhead.
- High elevation.
- Exact threshold boundary.
- Near horizon.
- Below horizon.
- Multiple stations and satellites.
- Two UTC timestamps.

It prints station geodetic/ECEF coordinates, satellite ECEF coordinates, frame, timestamp, elevation, range, policy, and visibility. It uses only synthetic records.
