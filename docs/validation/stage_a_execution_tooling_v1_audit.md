# SATNET Stage A Execution Tooling v1 Independent Audit

## Audit Scope

This was an independent, read-only audit of SATNET Stage A Execution Tooling v1. The audit inspected the execution path, independently exercised fail-closed controls with synthetic fixtures, reproduced deterministic planning identities, verified proposal and frozen-contract bytes, and verified the protected frozen production evidence before and after audit work.

No Stage A simulation, replay, acceptance, holdout unsealing, Stage B work, model training, production execution, merge, push, or tag mutation was performed. Audit-only scripts, tests, evidence, and this report were added outside the protected execution package.

## Preflight and Root Isolation Audit

`run_preflight` checks the frozen contract, plan hash, authorization, output-root states, root isolation, parent writeability, disk space, dependencies, and conflicting campaign locks.

However, `generate`, `resume`, `replay`, and `accept` do not invoke `run_preflight`. Their handlers proceed directly after authorization validation. The execution APIs also do not enforce `validate_output_roots`. Mandatory preflight and protected-root isolation can therefore be bypassed on the actual execution path.

Preflight also does not invoke the frozen production evidence verifier before scientific execution.

All four reserved Stage A roots remained absent throughout the audit.

## Generation, Ledger, Atomicity, and Resume Audit

The ledger state vocabulary and transition graph are explicit, ledger hashes are recomputed on write, JSON writes are atomic, and temporary run directories are renamed into final locations. Resume binds contract, plan, authorization, tooling, operation, partition, run count, roots, run records, and seeds. Completed artifact inventories are reverified, and retry of failed/interrupted runs is explicit.

Binding defects remain:

- Any nonempty adapter output can be inventoried and marked `SUCCEEDED`; no exact required artifact set, scientific metadata schema, run identity, seed identity, partition identity, or unexpected-artifact rejection is enforced before success.
- Only a campaign lock is acquired. No per-run lock exists.
- `lock_is_stale` is not integrated into generation or replay, and no validated stale-lock recovery/process-ID-reuse workflow exists.

## Replay and Acceptance Audit

Replay verifies source artifact inventory bytes and performs generation/replay scientific inventory comparison. Acceptance requires successful generation and replay records, re-verifies both artifact inventories, and checks replay equality flags and the plan run-record hash in each replay report.

Binding identity gaps remain:

- Replay does not bind the source generation ledger's plan hash, authorization hash, tooling identity, output roots, run-record hashes, or seed set to the authorized replay plan.
- Acceptance does not bind generation/replay ledger plan hashes, authorization hashes, output roots, ledger run-record hashes, or seed sets before passing.

Synthetic negative tests demonstrated that replay accepts a generation ledger with a changed tooling commit after ledger rehashing and acceptance accepts a changed generation seed after ledger rehashing.

## Security Audit

Traversal with `..`, POSIX absolute paths, backslashes, and empty artifact paths was rejected. Existing roots, overlapping roots, and repository/worktree roots were rejected by the root validator. Artifact inventory rejects symlink/junction escape.

Observation: `C:/absolute` is accepted and converted to drive-relative `C:absolute`. It remains contained when joined to the campaign root, so no root escape was demonstrated, but explicit rejection would make the validator clearer and more fail-closed.

## Binding Findings

### BINDING-001: Tooling identity does not verify current executable bytes

Expected: execution is denied when executable bytes are dirty, modified, missing, or inconsistent with the stable executable inventory.

Observed: `tooling_identity` returns the last relevant commit and the inventory-file SHA-256 only. A synthetic uncommitted executable modification produced the same identity.

Required correction: verify exact allowlisted current bytes, inventory membership, path set, file types, line-ending policy, and clean tracked/untracked state before authorization validation and execution.

### BINDING-002: Execution paths bypass mandatory preflight and root isolation

Expected: every generate, resume, replay, and accept path performs preflight and protected-root validation before writes.

Observed: CLI handlers call execution operations directly after authorization validation.

Required correction: make preflight/root isolation an inseparable internal prerequisite of every write-capable operation, not a separate optional command.

### BINDING-003: Ledger permits false success

Expected: `SUCCEEDED` requires exact scientific output metadata and artifact membership.

Observed: any nonempty artifact inventory is sufficient.

Required correction: define and enforce an exact per-run output contract before the success transition.

### BINDING-004: Replay omits source generation identity binding

Expected: replay rejects changed plan, authorization, tooling, roots, run records, or seeds.

Observed: replay trusts the generation ledger by run ID and artifact inventory without validating those identities.

Required correction: independently validate the complete generation ledger identity against authorized replay inputs before executing any replay run.

### BINDING-005: Acceptance omits cross-ledger identity binding

Expected: acceptance verifies plan, authorization, roots, run records, and seeds across generation and replay.

Observed: these ledger identities are not bound before acceptance passes.

Required correction: independently validate both complete ledgers and their operation-specific plans, authorizations, roots, records, and seeds before comparison or acceptance.

### BINDING-006: Preflight omits frozen production evidence verification

Expected: preflight verifies the protected frozen evidence identities before scientific execution.

Observed: contract reload occurs, but frozen evidence verification is not called.

Required correction: include the read-only frozen evidence identity check in mandatory execution preflight.

### BINDING-007: Per-run locking and stale-lock recovery are absent

Expected: campaign and per-run locking deny duplicate execution while safely handling validated stale locks and PID reuse.

Observed: only a campaign lock exists; stale-lock inspection is unused and no recovery operation exists.

Required correction: implement per-run lock identities and a conservative, audited stale-lock recovery protocol.

### BINDING-008: Inventory byte identity is not portable to fresh Windows checkout

Expected: every inventory-bound path has identical bytes on the required fresh `core.autocrlf=true` Windows checkout.

Observed: 19 records mismatch checkout bytes, while two records bind checkout CRLF bytes rather than Git blobs.

Required correction: establish narrow byte-preservation attributes for every inventory-bound executable/test path and regenerate the inventory from one explicit byte domain.

### BINDING-009: Full proposal artifact reproduction is unavailable

Expected: all proposal artifacts can be independently regenerated byte-for-byte from checked-in deterministic code and explicit inputs.

Observed: no proposal artifact generator exists.

Required correction: add a deterministic proposal generator and independent reproduction test covering all proposal artifacts and the self-excluding inventory.

## Final Verdict

**NOT APPROVED FOR STAGE A DEVELOPMENT EXECUTION-AUTHORIZATION PREPARATION**

A separate remediation task must correct all binding findings, regenerate the proposal and inventory under a portable byte policy, and undergo a new independent audit before authorization preparation can proceed.
